## Superpowers

- No auto-invoke `using-superpowers`.
- Paths — spec `docs/superpowers/specs/<milestone>-<topic>.SPEC.md`; plans under `docs/superpowers/plans/<milestone>/` as `ROADMAP.md`, `<phase-num>-<plan-num>-<feature-name>.md`, `<phase-num>.PATTERN.md`, `<plan-basename>.SUMMARY.md` — `<milestone>` like `m1`, 2-digit phase/plan num restarting each phase (`01-01`, `01-02`, `02-01`). Roadmap and every plan carry `**Spec:** <path>` under title; plans also `**Roadmap:** <path>`.
- After `brainstorming`: save spec, make roadmap from it, recommend `writing-plans` in new session.
- Roadmap sections: target scope, confirmed decisions, plan checklist, global constraints, whatever else needed. Checklist entry: phase · plan ID `<phase-num>-<plan-num>` · topic · modules · spec chapters · prerequisite plans · deliverables · completion status.
- In `writing-plans` approved spec is truth, roadmap is scope + phase boundaries fixed up front. 2–5 tasks per plan, cut as vertical slices; split on any of: >5 files in one task, two subsystems, discovery mixed with implementation.
- Each `writing-plans` run plans exactly one phase; next run waits for that phase to execute, then drafts against code it landed, not an earlier plan's text. Flip each plan's checklist `completion status` planned → executed as it lands.
- Tighten `writing-plans` task anatomy: add `**Read first:**` after `**Files:**` (files it modifies, plus spec chapters and upstream `Interfaces · Produces` that are truth); keep `**Interfaces:**` exact; add `**Done:**` — verifiable assertions only (source greps, observable behavior, test commands, CLI output), never subjective wording. Keep steps as `- [ ]` checkboxes on the TDD cycle so SDD can track them: run steps give exact command and exact expected failure; implementation steps give signatures and few non-obvious decisions, no body. Name concrete files, types, methods, constants throughout — vagueness and pasted code both fail.
- In `writing-plans` paste only what executor cannot derive: test code, lines a build or config file gains (not whole file), compatibility-frozen fixtures, one worked example per repeating pattern. Describe rest — no `package`/`import` lines, homogeneous cases as input/expectation table, README as sections it must cover, snippet two tasks share hoisted into `<phase-num>.PATTERN.md`. Special case: test infrastructure is own contract — write it out.
- After SDD final whole-branch review and required verification pass: synthesize — not copy — temporary artifacts and review verdicts in `.superpowers/sdd/<plan-basename>/` into `<plan-basename>.SUMMARY.md`, commit only that file, then invoke `finishing-a-development-branch`; at `Present Options`, always `Merge back to <base-branch> locally`.
