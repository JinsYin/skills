# 合成算法与漂移检查

`sync` 和 `check` 两个子命令的实现细则。

## sync：重放 V 链

### 主流程

```
1. 收集       glob .product/spec/<产品线>/V*.md
2. 排序       按 frontmatter.version 升序（不要按文件名字典序，V10 会排到 V2 前面）
3. 过滤       跳过 status: superseded
4. 校验       版本连续、无重号、文件名 V{n}__ 与 frontmatter.version 一致
5. 初始态     V1（type: baseline）的七章内容
6. 逐版应用   对 V2..Vn 的变更清单逐行执行
7. 收尾       打溯源标记 → 写 CURRENT.md
```

第 4 步任一项失败：**停下报错，不写文件**。合出一份半对的 `CURRENT.md` 比不合更糟——它会被当成事实来源。

### 逐行应用

对每条变更清单：

| 操作 | 执行 | 前置校验失败时 |
|---|---|---|
| `ADD` | 把该 V 里对应的全量内容插入当前态。页面插到「页面规格」章，插入位置按信息架构里的导航顺序 | 目标**已存在** → 报错，问用户是不是该写 `MODIFY` |
| `MODIFY` | 用该 V「修改的页面」章里的内容**整段替换**对应小节 | 目标不存在 → 报错，列出最接近的候选定位符 |
| `RENAME` | 只换名字，内容不动 | 同上 |
| `MOVE` | 从原位置摘出，插到新位置。同步更新信息架构章的导航树 | 同上 |
| `REMOVE` | 删除该节点及其所有子节点（删 `page.x` 连带其 fields/actions） | 同上 |

**替换而非追加**：`MODIFY` 一个字段行，是拿新行换掉旧行，不是在表格里加一行。变更文件里给出的就是替换后的完整内容。

### 级联清理（`MOVE` / `REMOVE` 必做）

改一个节点会在别处留下残渣。实测跑一遍就会撞上，漏了就是一份自相矛盾的 `CURRENT.md`：

| 触发 | 必须连带处理 |
|---|---|
| `REMOVE page.x` / `MOVE page.x` 后原分组空了 | **删掉该空分组**，别在信息架构里留一个没有子项的分组名 |
| `REMOVE page.x` | 删掉角色权限矩阵里对应的列/行 |
| `REMOVE page.x` | 检查关键流程章、影响面是否还提到它——提到就是悬空引用，报给用户由他决定改还是删 |
| `REMOVE`/`RENAME` 涉及的术语 | 术语表同步删除或更名 |

级联清理**只做结构上必然的那几项**（空分组、权限矩阵列）。流程与术语的语义调整要报给用户确认，不要替他改——`REMOVE` 一个页面不代表引用它的流程就该删。

### `RENAME` 的历史别名放哪

- 目标**本身是术语表条目**（`term.x`）→ 更名并在术语表「备注」列写 `历史别名：<旧名>`
- 目标是字段或操作 → **不写进术语表**。术语表是对外称谓的锁定表，塞进字段旧名会把它变成垃圾场。旧名只留在 V 文件的变更清单里，追溯时去那儿查

### 边界条件

- **同一个 V 内多条操作命中同一目标** — 按表格里的书写顺序执行。`RENAME` 后紧跟的 `MODIFY` 应该用**新名字**的定位符（`spec-format.md` 要求拆成两行正是为此）
- **跨 V 的链式改名** — `V2` 把 A 改成 B，`V3` 把 B 改成 C。`V3` 的定位符必须写 B，不能写 A。写 A 时报错并提示「A 已在 V2 更名为 B」
- **`REMOVE` 后又 `ADD` 同名** — 允许，视为全新节点，溯源写 `V1 → V3（删除后重建）`
- **`draft` 版本** — 纳入合成，但 `CURRENT.md` frontmatter 打 `includes_draft: true`，且在「给 AI 设计工具的上下文」块末尾加一行醒目提示：本文件包含未定稿变更（V\<n\>）
- **只有 V1** — 正常合成，`synthesized_from: [1]`，`CURRENT.md` ≈ V1 内容加上下文块
- **产品线目录下无 V 文件** — 不生成 `CURRENT.md`，提示先 `init`

### 溯源标记

每个页面节末尾追加一行 blockquote：

```
> 来源：V1 → V2（移动分组、字段改名）→ V3（新增批量操作）
```

括号里是**该页面在那一版发生了什么**，不是那一版的整体标题。只在 V1 出现过、之后没动的页面写 `> 来源：V1`。

放在节末而不是节首——设计工具读页面规格时不会被元信息打断。

### 写出

按 `templates.md` 的 `CURRENT.md` 骨架写。注意：

- 第一行必须是 GENERATED 注释，在 frontmatter **之前**
- 「给 AI 设计工具的上下文」块每次重新生成，其中技术栈与视觉规范路径从项目 CLAUDE.md / 现有 `tokens.css` 探测，探不到就沿用上一版 `CURRENT.md` 里的值
- 第七章「明确不做」原样保留并合并各 V 的增删——**别在合成时优化措辞**，那章的价值全在具体

## check：一致性与漂移

只读。逐项报 ✅ / ⚠️ / ❌，每个问题给具体修法。

### 结构类

| 项 | 判据 | 级别 |
|---|---|---|
| 目录存在 | `.product/spec/` 有 V 文件 | 无则 ⚠️「尚未 init」，**不是错误** |
| 版本连续 | 无重号、无跳号 | ❌ |
| 文件名一致 | `V{n}__<slug>.md` 对上 frontmatter 的 `version` 与 `slug` | ❌ |
| product 一致 | frontmatter `product` == 所在目录名 | ❌ |
| 唯一 baseline | 每产品线恰好一个 `type: baseline` | ❌ |

### 快照新鲜度

| 项 | 判据 | 级别 |
|---|---|---|
| 覆盖完整 | `synthesized_from` 含目录下所有非 superseded 的 V 版本号 | ❌ 提示跑 `sync` |
| 未被手改 | `CURRENT.md` mtime 晚于任一 V 文件的 mtime，且首行 GENERATED 注释与 frontmatter 完整 | ⚠️ 疑似手改，提示改动会在下次 sync 丢失 |
| draft 提示 | `includes_draft: true` 时提醒当前态未定稿 | ⚠️ |

mtime 判据会误报（git checkout 会重置 mtime），所以是 ⚠️ 不是 ❌，措辞用「疑似」。

### 内容类

| 项 | 判据 | 级别 |
|---|---|---|
| 定位符可解析 | 每条变更在其前序态里能命中（`ADD` 要求不命中） | ❌ |
| 悬空引用 | 被 `REMOVE` 的目标仍被后续 V、流程章、术语章引用 | ❌ |
| 视觉污染 | 正文出现 `#[0-9a-fA-F]{3,8}`、`\d+px`、`rem`、`font-family`、`rgb(` | ⚠️ 违反纪律 4，列出行号 |
| 文案泄漏 | 出现项目 CLAUDE.md 标记为不得对外的内部代号 | ❌ |
| 六小节完整 | 每个页面节有齐标识/目标/布局骨架/数据与字段/操作/状态与流转 | ⚠️ 列出缺哪节 |
| 遗留 TODO | 正文含 `<!-- TODO` 或 `<>` 占位符未填 | ⚠️ 列出位置 |

### 与实现的漂移（可选，代价高）

只在用户明确要求时跑。拿规范里的页面 id 去前端代码里找：

- 规范有、代码无 → 规范超前或已废弃的功能没删
- 代码有、规范无 → 功能上线了没补规范

这项只报事实，**不要自动判断谁对**——两种情况都合法（规范可以超前于实现）。
