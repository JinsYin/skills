# nestjs-best-practices

NestJS 11 + Node 22 + Drizzle on GaussDB / openGauss. 54 rules, 9 categories.

Structure modeled after [spring-boot-best-practices](../spring-boot-best-practices/) and [vercel-labs/agent-skills](https://github.com/vercel-labs/agent-skills/tree/main/skills/react-best-practices).

## Why this layout

Two ways to feed conventions to an agent:

| | Path injection (`.claude/rules` + `paths:`) | Progressive disclosure (this layout) |
|---|---|---|
| Loading | Auto-injects the full file on a glob match | Agent reads the index, then opens one rule |
| Granularity | One large file per topic | One small file per rule |
| Failure mode | Wrong glob never matches, or matches everything | Weak index misses the rule |
| Addressability | No slug | Stable slug; reviews cite the rule by name |

## Layout

```
SKILL.md            Index: 54 slugs + one-line summaries + task routing table
rules/
  _sections.md      Category definitions (build input)
  _template.md      Single-rule skeleton
  <prefix>-<slug>.md
AGENTS.md           Full compiled bundle, generated by scripts/build.sh
scripts/build.sh    _sections.md + rules/*.md → AGENTS.md
metadata.json       Version, abstract, references
```

## Impact levels

Graded by **consequence of violation**, not frequency:

| Level | Meaning | Categories |
|---|---|---|
| CRITICAL | Immediate bug, security hole, or startup/runtime failure | `layer-` `auth-` `crypto-` `orm-` |
| HIGH | Runs, but fails review and forces rework | `db-` `envelope-` `dto-` |
| MEDIUM | Inconsistent, though functionally valid | `naming-` |
| LOW | Style preference | `stack-` |

Three `db-` rules are CRITICAL on their own: driver alias, pool error handling, and banning `drizzle-kit push`.

## Adding a rule

1. Copy `rules/_template.md` to `rules/<prefix>-<slug>.md`, using a prefix from `_sections.md`.
2. State why and the consequence of violation. A bare imperative gets low compliance.
3. Add one index line under the matching category in `SKILL.md`.
4. Rebuild: `bash scripts/build.sh`.
5. Check index/file parity:

```bash
index_file="$(mktemp)"
rules_file="$(mktemp)"
trap 'rm -f "$index_file" "$rules_file"' EXIT
grep -oE '^- `[a-z]+-[a-z-]+`' SKILL.md | tr -d '`' | sed 's/^- //' | sort > "$index_file"
ls rules/[a-z]*.md | xargs -n1 basename | sed 's/\.md$//' | sort > "$rules_file"
diff "$index_file" "$rules_file" && echo OK
```

An extra index entry breaks `Read`. A missing index entry hides the rule. Run the check after every change.

## Enabling

```bash
mkdir -p "$HOME/.claude/skills"
ln -s "$(pwd)/skills/nestjs-best-practices" \
      "$HOME/.claude/skills/nestjs-best-practices"
```

Symlink rather than copy. This repository stays the source of truth.

## Boundaries

Cross-project baseline. Package names, topology, and locked decisions live in project `CLAUDE.md`, which wins on conflict.

Leave rule text in this skill. A pasted copy in `CLAUDE.md` loads every session and drifts.
