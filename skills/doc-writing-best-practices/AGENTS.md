## 1. 中文排版


### 中文与西文、行内代码之间加空格

与数字同理，中文与拉丁字母、行内代码之间也需要半角空格分隔。行内代码尤其明显——反引号渲染成带背景色的方块后，紧贴中文会显得挤压。

**错误：**

```markdown
用Kustomize管理overlay，执行`kubectl apply`即可。
```

**正确：**

```markdown
用 Kustomize 管理 overlay，执行 `kubectl apply` 即可。
```

**标点旁不加**：中文标点已含空白，`执行 `kubectl apply` 即可。` 中句号前不再补空格。

这条是 LOW，因为它不影响理解。但在同一份文档里时加时不加，比统一不加更显得潦草——**一致性比选哪一种更重要**。


### 中文与数字之间加空格

中文字符与阿拉伯数字紧贴时，字形密度骤变，读者需要额外一次视觉停顿来切分。加一个半角空格即可消除。

**错误：**

```markdown
迁移在2024年完成，共28条规则，耗时3天。
```

**正确：**

```markdown
迁移在 2024 年完成，共 28 条规则，耗时 3 天。
```

**例外**：数字与紧随其后的量词、单位若构成固定搭配，且中间无中文（如 `3ms`、`8GB`、`第 3 章` 中的"第"字后不加），按可读性判断，不必机械插空格。

行内代码同理：`共 28 条` 中若 `28` 写成 `` `28` ``，反引号外侧仍需空格。


### 中文句子使用中文标点

中文全角标点自带字符间距，与中文字形宽度匹配；混用半角标点会让行内节奏突然变紧，且逗号、句号在中文语境下几乎贴到前一个字上。

| 用 | 不用 |
|---|---|
| `，` `。` `！` `？` | `,` `.` `!` `?` |
| `（）` `《》` | `()` `<>` |
| `、`（并列） | `/` |

**错误：**

```markdown
这条规则有三个前提: 已安装 Node(版本 20+), 已配置代理, 且网络可达.
```

**正确：**

```markdown
这条规则有三个前提：已安装 Node（版本 20+）、已配置代理，且网络可达。
```

**例外**：纯英文句子、代码、路径、命令、以及行内代码块内部一律保持半角。判据是**这一段的主语言是什么**，不是整篇文档是什么。

## 2. 文档结构


### 代码块必须标注语言

不带语言标注的围栏代码块不会被高亮，几十行的配置或代码就变成一片等宽灰字。标注的成本是几个字符。

**错误：**

````markdown
```
FROM node:24-alpine
RUN corepack enable
```
````

**正确：**

````markdown
```dockerfile
FROM node:24-alpine
RUN corepack enable
```
````

常见标注：`bash` `java` `tsx` `ts` `sql` `yaml` `dockerfile` `json` `markdown` `diff`。

**标注要准确**：把 YAML 标成 `json` 比不标更糟——高亮会按错误的语法着色，读者据此判断结构就会出错。

**纯输出用 `text`**：终端输出、日志片段、目录树没有对应语言时显式标 `text`，表明"这里确实不需要高亮"，而不是忘了标。


### 标题层级不跳级，一篇只有一个 H1

H1 之后直接跳到 H3，在渲染上"看起来"只是字号差异，但目录生成器、锚点导航、以及把文档喂给检索系统的工具都依赖层级推断从属关系——跳级会让 H3 被挂到错误的父节点下。

**错误：**

```markdown
# 部署指南

### 前置条件      ← 跳过了 H2

### 步骤
```

**正确：**

```markdown
# 部署指南

### 前置条件

### 步骤

### 步骤一：构建镜像
```

一篇文档只应有一个 H1，即文档标题。用 H1 做章节分隔会让文档看起来像多篇拼接。

**层级深度控制在 H4 以内。** 需要 H5、H6 通常说明这一节该拆成独立文档了——读者在第四层已经很难保持对上下文的记忆。


### 链接多或有重复目标时用参考链接

判据：**全文链接超过约 5 个，或同一目标被引用不止一次**——改用参考链接；少量一次性链接保留行内形式。

长 URL 混在正文里会把列表项撑成好几行，源码难读、diff 难审；同一目标内联多处时，改地址要改多处，漏一处就是死链。

**正文**用折叠式 `[文本][]`，链接文本即标签；同一文本指向不同目标、或不同文本指向同一目标时，才用完整式 `[文本][标签]`：

```markdown
- 调研记录：[API 网关产品能力调研][]、[多环境隔离调研][]
- 文档链接：[Envoy Gateway Concepts][]
```

**定义**集中放在文末，用 HTML 注释分组（渲染时不可见）：本地文件在前，外部 URL 在后；组内按首次出现排序，便于对照正文核对：

```markdown
<!-- 文件链接（调研记录） -->
[API 网关产品能力调研]: ../research/api-gateway-product-capabilities.md
[多环境隔离调研]: ../research/api-gateway-multi-env-isolation.md

<!-- URL 链接（技术参考） -->
[Envoy Gateway Concepts]: https://gateway.envoyproxy.io/docs/concepts/
```

**两个静默失效**：未定义的引用会原样渲染成 `[文本][]` 字面量；删正文时漏删的定义不报错，只会堆积。改完核对引用与定义一一对应，markdownlint 的 MD052 / MD053 可查。


### 有共同维度用表格，无共同维度用列表

判据只有一条：**这些条目是否都在回答同一组问题？**

是——用表格，读者可以纵向比较：

```markdown
| 环境 | 副本数 | 镜像 tag | 命名空间 |
|---|---|---|---|
| 预发 | 1 | latest | app-pre |
| 生产 | 3 | 版本号 | app |
```

否——用列表，强行塞进表格会产生大量空单元格：

```markdown
- **前置条件**：已安装 Docker 与 kubectl
- **注意**：首次部署需手工创建 Secret
- **回滚**：`kubectl rollout undo deployment/app`
```

**表格里不要放长段落。** 单元格无法换行控制，长文本会把列宽撑到需要横向滚动。超过一两句就改用列表 + 小标题。

**超过 5 列考虑转置或拆分**：窄屏下横向滚动的表格实际上没人会看完。

## 3. 内容质量


### 示例要能直接抄用，不用占位符敷衍

`foo` / `bar` / `<your-value-here>` 这类示例把补全的责任推给读者。补全需要的恰恰是文档没写的那部分知识——于是要么抄错，要么回来问。

**弱：**

```bash
docker build -f <dockerfile> --build-arg <key>=<value> -t <tag> .
```

**强（用项目真实会出现的值，可直接粘贴执行）：**

```bash
docker build -f deploy/docker/Dockerfile.backend \
  --build-arg MODULE=dap-admin \
  -t dap-admin:latest .
```

确实需要读者替换的部分，用**语义明确的大写占位**并紧跟一行说明来源：

```bash
export NEXUS_PASSWORD=<你的 Nexus 密码，见密码管理器 "内网 Nexus" 条目>
```

**错误示例必须标注错在哪。** 只贴一段"错误写法"而不说明为什么错，读者只会记住形状、记不住原因，下次换个形状照犯。


### 写清为什么，而不只是写做什么

只描述操作的文档有个致命缺陷：**读者无法判断它在当前情况下是否还适用**。遇到与文档描述略有出入的场景时，只能照抄或放弃，没有第三种选择。

**弱：**

```markdown
本地构建必须加 `-P opengauss` 参数。
```

**强：**

```markdown
本地构建必须加 `-P opengauss`：父 pom 里 `gaussdb` 是 `activeByDefault=true`，
不加会把 GaussDB 驱动打进 jar，连本地 openGauss 容器时协议不兼容。
报错出现在运行期连库那一刻，与构建命令相距很远，很难反查到是 profile 的问题。
```

后者让读者能自己推断：换了数据库要不要继续加、遇到类似的"构建期决定运行期行为"的问题该怎么查。

**尤其要写的三类"为什么"**：

- **反直觉的决定** —— 不写就会被"优化"掉
- **踩过的坑** —— 包括当时的错误现象，便于下次按现象搜到这里
- **例外与边界** —— 什么情况下这条不适用
