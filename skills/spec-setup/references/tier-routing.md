# 分诊判例

决策树在调用方的 `SKILL.md`（`spec-setup` 与 `spec-triage` 共用这份判例）。这里是边界情形的判例——难点从来不在典型案例，而在"看起来两边都行"的那些。

新项目场景下"常见误判"一节照样适用：误判往往在**播种的那一刻**就发生了，只是要等代码写出来才看得见。

## 第一问：通用还是本项目？

判定方法：**把项目名换掉，这条还成立吗？**

| 约定 | 换项目后 | 判定 |
|---|---|---|
| Controller → Service → Mapper 单向依赖 | 成立 | 通用 |
| 包名锁定 `com.shdatagroup.dap.*` | 不成立 | 本项目 |
| 主键用 `IdType.ASSIGN_ID` 禁 `AUTO` | 成立 | 通用 |
| Flyway 分 base/centralized/distributed 三层 | 不成立（层数是本项目部署拓扑决定的） | 本项目 |
| 迁移必须多方言同版本号同步 | 成立 | 通用 |

注意最后两行的切分：**「必须同步」是通用的，「分几层、哪几层」是项目的。** 同一个主题常常需要拆开路由，不要因为它们写在一起就整块搬运。

## 常见误判

### 误判一：把通用规范写进 CLAUDE.md

**症状**：CLAUDE.md 里出现 DTO 命名表、MapStruct 用法、Controller 方法排序。

**代价**：每会话、每子代理都为其他项目也适用的内容付费。一个 7.7 KB 的命名规范放进常驻层，跑一轮多代理规划就是几万 token。

**处理**：搬进通用 skill，CLAUDE.md 只留一行指向。

### 误判二：把项目决策写进通用 skill

**症状**：skill 里出现具体类名、具体表名、"本项目 Phase 14 决定…"。

**代价**：污染其他项目——它们会读到不适用的约束，且无从判断该不该遵守。

**处理**：迁回项目的 CLAUDE.md。若该决策**明确要求不得被审查反转**（如"不得以敏感信息泄漏为由删除"），必须放 CLAUDE.md 而非项目文档，因为只有常驻层能保证代码审查时它在场。

### 误判三：用 `paths:` 覆盖文档与工作流产物

**症状**：`paths:` 里出现 `**/*.md`、`docs/**`，或项目所用工作流的产物目录通配（例如某阶段化工作流的规划目录或其他任务产物目录；具体路径随工作流而变）。

**动机通常是**："想让写方案/做规划的 agent 也看到规范。"

**代价**：这些文件在写代码之前必然被读写，于是**全部**带此 glob 的规则无差别注入，与本次改动的技术栈无关。路径作用域被完全废掉。

**处理**：删掉这些 glob。前期需要的是「有哪些硬约束」，那属于 CLAUDE.md；细则应在真正编辑对应源文件时命中——那时更靠近编辑动作，遵守率反而更高。

### 误判四：为极少内容单独建 skill

**症状**：一个 skill 只有 2～3 条规则，或总量不足 2 KB。

**代价**：skill 的固定开销（索引 + 触发判断）超过内容本身。

**处理**：放 `.claude/rules` 加窄 glob，或并入已有的对口 skill。**判断阈值**：内容够不够分出 3 个以上分类、10 条以上规则；不够就别建。

### 误判五：无 frontmatter 的规则文件

**症状**：`.claude/rules/` 下某文件没有 `paths:`。

**代价**：无条件常驻，等价于 CLAUDE.md 的成本，但读者不会去 CLAUDE.md 找它。

**处理**：要么补 `paths:`，要么把内容并进 CLAUDE.md。**例外**：内容极小（百字节量级）且确实全局适用时，可保留，但要在审计时明确认定这是有意为之。

## 拆分时机

单个规则文件超预算时，按**触发条件**拆而不是按主题拆：

```
04-naming-conventions.md (7.7 KB，混装)
  ├─ 包结构        → naming-package-layout
  ├─ 类名后缀表    → naming-class-suffix
  ├─ Controller 方法 → naming-controller-methods
  ├─ Service/Mapper 方法 → naming-service-mapper-methods
  ├─ 枚举与常量    → naming-enum-constants
  ├─ URL           → naming-url
  ├─ 实体主键      → entity-tableid-assign-id   ← 换了分类
  └─ 表/列/索引命名 → db-*                      ← 换了分类
```

注意后两项：拆分时**允许跨分类重新归属**。原文件把它们放一起是因为都叫"命名"，但实际触发条件完全不同——改实体和改 URL 不是同一件事。

## 何时不动

以下情况保持现状，不要为了整齐而搬：

- 内容正确、位置正确、体量在预算内
- 位置略欠佳但搬运会制造悬空引用，且收益 < 1 KB
- 用户明确说过要保留在某处
