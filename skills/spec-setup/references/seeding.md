# 播种：四层的初始内容

分层判据见 `tier-routing.md`，规则写法见 `rule-authoring.md`。这份只讲**新项目的初始形态**——写什么、写多少、以及怎么把留白记成可执行的东西。

## 预算：写不满是正常的

| 层 | 新项目上限 | 对比 `spec-triage` |
|---|---|---|
| `CLAUDE.md` | **60 行** | 150 行 |
| `.claude/rules` 单文件 | 60 行 | 相同 |
| 项目文档 | 不限 | 相同 |

收紧到 60 行是因为新项目大部分还没裁决。**写满 60 行要警惕**：回头逐条问自己"这条谁拍过板"，答不上来的删掉，记进留白。

## CLAUDE.md 骨架

```markdown
# <项目名>

<一句话：这是什么，给谁用。>

## 技术栈

- 后端：Spring Boot 3.5.x + Java 21 + MyBatis Plus（Context7 核对于 2026-08-12）
- 前端：React 19.x + shadcn/ui（同上）
- 小程序：原生 + TypeScript（无对口 skill，规范见 .claude/rules/miniapp/）

## 已启用规范 skill

- `spring-boot-best-practices` —— 后端编码与架构纪律
- `frontend-ui-best-practices` —— 前端界面与交互
- `devops-best-practices` —— 容器化与部署
- `doc-writing-best-practices` —— 中文技术文档

**不要把这些 skill 的内容复制到本文件**，启用即可。

## 模块布局

server/   后端服务
web/      Web 前端
miniapp/  小程序

## 锁定决策

<只写已拍板、违反即打回的。每条一句话，带后果。没有就留空。>

## 规范复查触发点

<见下节>
```

「技术栈」「已启用 skill」「模块布局」三节是继承来的，几乎不占决策成本。真正要克制的是「锁定决策」。

## 复查触发点小节

必须落 `CLAUDE.md`，不能只放项目文档——只有常驻层能保证它在场。三到五行：

```markdown
## 规范复查触发点

当前留白：命名细则、错误码编排、测试分层——首个模块落地后回来定。
触发点：首个模块合并后、首次代码审查后、引入第二个形态时，跑 `spec-triage --check`。
未决 glob：`server/**/*.java`（目录未建，命中数 0，待落地后复核）。
```

三行各有职责，缺一不可：

- **留白清单** —— 没有这行，留白就等于遗漏，后来者无从区分"没想到"和"故意没定"
- **触发点** —— 没有这行，留白永远不会被补
- **未决 glob** —— 目录尚未存在的 `paths:` 在这里挂账，否则就是沉默失效的空 glob（`guards.md` G3）

## .claude/rules 的初始形态

只放**推荐得来的缺口规范**——继承的内容在 skill 里，不要落地成文件。

`paths:` 用第 2 步的模块映射锚定：

```yaml
---
paths:
  - miniapp/**/*.ts
  - miniapp/**/*.wxml
---
```

不要写 `**/*.ts`（会命中 Web 前端与 Node 脚本）。不要写 `docs/**`、`**/*.md`、工作流产物目录（`guards.md` G1）。

**目录还没建时**：可以写，但必须同时记进 `CLAUDE.md` 的「未决 glob」。写了不记 = 一条永不生效且无人知晓的规则。

## 项目文档：选型记录

放 `docs/` 或项目约定的位置，记三样东西：

```markdown
## 选型记录（2026-08-12）

| 决策 | 选择 | 理由 | 被推翻的方案 |
|---|---|---|---|
| 后端语言 | Java 21 | 团队熟悉；`spring-boot-best-practices` 的 40 条规范可直接继承 | Go——无硬性理由，且规范要从零建 |
| 小程序 | 原生 + TS | 单目标，跨端抽象层只剩成本 | Taro——多端时重新评估 |
```

**「被推翻的方案」这列最容易省掉，也最值钱**。没有它，三个月后有人会重新提出同一个方案，而当初的理由已经没人记得。

## 不要在初始化时做的事

- **不要复制通用 skill 的内容进 `CLAUDE.md`** —— 继承的是 skill，不是它的文本。复制一份必然与源漂移（`guards.md` G4）
- **不要为零覆盖形态当场建 best-practices skill** —— 代码还没写就抽通用规范，正是猜写。等累积够量（3 个以上分类、10 条以上规则）再用 `skill-creator`
- **不要写测试规范、日志规范、错误码编排的细则** —— 除非用户明确拍过板。这三样是留白清单的常客
- **不要建空目录占位** —— 本 skill 只产规范层，不碰工程配置与脚手架
