# REQUIREMENTS.md 结构规范

## 章节与必须确认的信息

### 标题与说明

必须确认项目的对外名称。标题格式：

```markdown
# <项目名称> - 产品原始需求

> **说明**：本文档记录项目启动初期的原始需求，在后续的产品演进与版本迭代过程中可能略有差异，以最终实现为准。
```

### 1. 项目定位与核心能力

#### 1.1 项目定位

必须确认：

- 产品/项目解决的核心问题与提供的价值。
- 目标用户、使用方或所在业务体系。
- 产品在整体系统中的角色与边界。

用短语加说明的无序列表表达，每一项只讲一个定位维度。

#### 1.2 核心能力

必须确认至少一项核心能力。每项写清能力名称、主要行为和预期结果；不要混入尚未确认的实现细节。

### 2. 产品交付矩阵

必须确认至少一种交付形态。每项应覆盖：

- 交付物名称与形态（服务、SDK、Starter、组件库、CLI 等）。
- 主要使用方。
- 集成、分发或部署方式。
- 用户明确给出的技术约束；未指定时不要补选型。

用编号列表表达。一个交付物包含子能力时，在该项下使用缩进列表。

### 3. 产品功能调研

必须确认本阶段是否需要产品/竞品调研。

若需要，对每个对象确认：产品名称、目标功能/页面、文档链接（若有）、希望验证的功能边界或业务问题。不要把「待调研」写成「已支持」。

若不需要，写：

```markdown
> 经确认，本阶段不设置产品功能调研项。
```

### 4. 技术实现参考

必须确认是否存在技术实现参考，以及这些参考是否只是启发而非既定选型。

若存在，对每项确认：项目/文档名称、链接（若有）、具体参考范围。章节开头统一写：

```markdown
> ⚠️ **说明**：以下项目或资料仅作为技术实现与架构设计参考，不代表复制、模仿或最终技术选型。
```

若不存在，写：

```markdown
> 经确认，本阶段不指定技术实现参考。
```

```markdown
# <项目名称> - 产品原始需求

> **说明**：本文档记录项目启动初期的原始需求，在后续的产品演进与版本迭代过程中可能略有差异，以最终实现为准。

## 1. 项目定位与核心能力

### 1.1 项目定位

- **<定位维度>**：<问题、价值、对象或边界>。

### 1.2 核心能力

1. **<能力名称>**：<主要行为与预期结果>。

---

## 2. 产品交付矩阵

1. **<交付物名称>**：<交付形态、使用方和接入/部署方式>。

---

## 3. 产品功能调研

> <调研范围说明，或经确认不设置调研项>。

1. **<产品名称> - <目标功能>**
   - 文档链接：[<链接文本>](<URL>)
   - 调研目标：<要验证的问题或边界>。

---

## 4. 技术实现参考

> ⚠️ **说明**：以下项目或资料仅作为技术实现与架构设计参考，不代表复制、模仿或最终技术选型。

1. **<项目或资料名称>**
   - 项目地址：[<链接文本>](<URL>)
   - 参考范围：<准备参考的机制或设计>。
```

删除所有未使用的模板条目，但不要删除四个编号章节。没有链接时省略链接行，并明确链接未提供；不得猜测或搜索补齐，除非用户另行要求。
