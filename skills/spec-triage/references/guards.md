# 硬闸

落地前逐条过。**命中即停下报告，不要自行放宽。** 每条都对应一次实际发生过的故障。

## G1 — `paths:` 禁止覆盖规划期

**判定**：`paths:` 中出现 `.planning/**`、`**/*-PLAN.md`、`**/*.md`（`markdown.md` 这类真正的 md 格式规则除外）。

**为什么**：规划命令必然读写 PLAN.md，一旦命中就等于无条件常驻，路径作用域彻底失效。实测：11 个文件都带这条 glob，任意 `plan-phase` 无差别注入 36788 B，且 planner / plan-checker / executor 各付一遍。

**处理**：删掉该 glob。若真需要规划期看到，说明那条约定属于 CLAUDE.md，不属于路径注入层。

## G2 — glob 必须锚到模块

**判定**：出现裸 `**/*.java`、`**/*.ts` 这类全仓通配。

**为什么**：仓内往往有多个技术栈或生成物目录，全仓通配会在无关文件上命中。

**处理**：改成 `<模块>/**/*.java`。若确实全仓适用（如 markdown 格式规则），显式确认后放行。

## G3 — glob 必须真能命中

**判定**：对每个 `paths:` 条目跑一次实际匹配，命中数为 0 即失败。

**为什么**：写错的 glob **不报错**，规则只是永远不生效。实测：某前端规则 `paths` 写 `**/*.vue`，而项目零个 `.vue`、组件全是 `.tsx`——该规则从未命中过，且描述里还写着另一个框架的名字。

**检查**：

```bash
# 对每条 glob 确认命中数 > 0
git ls-files '<glob>' | head -1
```

## G4 — 禁止跨层重复

**判定**：同一条约定在 CLAUDE.md、skill、`.claude/rules` 中出现两次以上。

**为什么**：两份副本必然漂移，且读者不知道该信哪份；常驻层的重复还要按会话数累计付费。

**处理**：保留成本最低的那层，其余删除，在保留处补指向说明。

## G5 — 预算

| 层 | 上限 |
|---|---|
| `CLAUDE.md` | 150 行 |
| skill 索引 | 200 行 |
| skill 单条规则 | 80 行 |
| `.claude/rules` 单文件 | 60 行 |

超出时**回压到下一层**，不是放行。

## G6 — 删除前必须做覆盖度比对

**判定**：任何删除操作前，逐条确认待删内容已被目标层覆盖。

**为什么**：整块搬运时容易漏掉夹在中间的条目。实测一次迁移差点丢三处：Sa-Token 权限注解约定（夹在分层规则的代码示例里）、字段类型约定（夹在 API 信封文件的 Shape rules 小节）、以及一条**明确写着"不得删除"的锁定决策**。

**方法**：把待删文件的每个小节列出来，逐节标注去向（已覆盖 / 需新增 / 需迁移 / 确认丢弃）。全部标注完才能删。

## G7 — 删除后必须查悬空引用

**判定**：`grep` 全仓找指向已删文件的引用。

**为什么**：其他 skill / command 里的 `@path` 文件引用失效时**不报错**，只是那段约束静默消失。实测：删掉一个 UI 规则文件后，某个 skill 传给下游的约束块里仍引用它，导致视觉规范被静默丢弃。

**检查**：

```bash
grep -rn '<被删文件名>' .claude/ CLAUDE.md AGENTS.md *.md 2>/dev/null
```

删前删后各查一次。

## G8 — skill 索引与文件严格一一对应

**判定**：索引中列出的每个 slug 都有对应文件，每个规则文件都在索引中出现。

**为什么**：索引式结构唯一的沉默故障。索引多写 → agent `Read` 失败；索引漏写 → 规则永远不被发现。

**检查**：

```bash
grep -oE '^- `[a-z]+-[a-z-]+`' SKILL.md | tr -d '`' | sed 's/^- //' | sort > /tmp/i.txt
ls rules/[a-z]*.md | xargs -n1 basename | sed 's/\.md$//' | sort > /tmp/f.txt
diff /tmp/i.txt /tmp/f.txt && echo OK
```

同时确认索引里的分类条数与实际文件数一致——改动后忘了同步计数很常见。

## G9 — 编译产物必须重建

**判定**：skill 带 `scripts/build.sh` 时，规则改动后是否重跑。

**为什么**：`AGENTS.md` 之类的全量版是给其他 agent 工具消费的，不重建就与规则源不一致，而它不会自己报错。

## G10 — 永不写入只读位置

**判定**：不得写入 plugin 安装目录、`node_modules`、任何随更新重建的缓存路径。

**为什么**：这些位置的改动会在下次更新时静默丢失。
